# Join keys by agent tool session, and one credential precedence

Superseded in part by [ADR 0049](0049-inside-an-agent-tool-a-joined-session-beats-cookout-token.md) (2026-11-23, mattpocock/cookout#150): inside an agent tool the credential is `COOKOUT_SESSION`, then the joined session, then `COOKOUT_TOKEN`; the precedence below is as it stood before.

Superseded in part on 2026-11-26 by [ADR 0108](0108-a-codex-join-keys-by-its-thread.md), in this fork (mfroembgen/cookout): Codex keys a join by `CODEX_THREAD_ID`, so it is no longer a tool with no session variable.

2026-11-23 (mattpocock/cookout#116). Builds on [ADR 0042](0042-agent-session-tokens-replace-the-lease.md) and [ADR 0038](0038-a-human-token-from-an-agent-tool-is-refused-unless-overridden.md). That `cookout join` inside an agent tool makes the whole agent tool session act as the joined agent, keyed by the tool's session ID, is Matt's decision of 2026-11-23, recorded on #116, as are `--print-env`, `COOKOUT_SESSION` and the precedence below. The refusal codes (`not_joined`, `already_joined`, `agent_tool_missing`, `agent_tool_session_missing`), keying the state file by server as well, and `whoami`'s `summary` field are chief-of-staff choices, pending Matt's review.

ADR 0042 kept a joined agent session token in one state file per server and Identity token. Two sessions with the same token shared one, unless each had its own `COOKOUT_STATE_DIR`, and a subagent couldn't tell which session it belonged to. An agent tool already names its session: Claude Code sets `CLAUDE_CODE_SESSION_ID`, and its subagents share their parent's (checked on Claude Code 2.1.330). So the session tree is the agent.

- **Join keys by session.** Inside a detected agent tool, `join --as <name>` sends `COOKOUT_TOKEN` (the agent's Identity token), and keeps the agent session token it was issued in a state file named by a hash of the tool, its session ID and the server's URL. Every later verb in that session and its subagents sends it; `leave` revokes it and deletes the file. The session ID's variable sits in the agent tool list in `app/modules/config/index.ts` beside the tool's markers, so another tool is one entry more. A tool with no session variable (every one but Claude Code for now) makes `join` refuse with `agent_tool_session_missing`.
- **One join per session.** A second `join` in a joined session is refused with `already_joined`, naming the agent it already is. Outside an agent tool, `join` is refused with `agent_tool_missing`.
- **`--print-env` stores nothing.** It issues an agent session token and prints `export COOKOUT_SESSION=...`, for one subagent or script that should act as another agent, or for a process outside an agent tool.
- **`COOKOUT_SESSION` holds an agent session token**, which the CLI and the SDK's environment defaults send.
- **Credential precedence**, first match wins: `COOKOUT_TOKEN`, then `COOKOUT_SESSION`, then the agent session this agent tool session joined, then the Login, only when no agent tool is detected (`COOKOUT_ALLOW_HUMAN=1` doesn't change detection here). Inside an agent tool with none of these, every verb but `join`, `login` and `logout` is refused with `not_joined`: "join as an agent first: cookout join --as <name>". An explicit variable wins over what is stored, so a person can always say who to act as.
- **`whoami` names the source**: `source` is `COOKOUT_TOKEN`, `COOKOUT_SESSION`, `agent session token` (with `joinedAt`) or `login`, and `summary` reads like `release-bot (agent session token, joined 2 h ago)`.

The state file is keyed by server too, so a session that joined one cookout never sends that token to another `COOKOUT_URL`.
